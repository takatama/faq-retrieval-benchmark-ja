# 両記事で共通して使うデモの紹介

[デモのソースとCodePenへの持ち込み手順](../demo/faq-search/README.md)。

## 前回の記事に加える文

この記事で考えているのは、自然な言葉で質問すると、既存のFAQから読むべきものを探せるアプリです。候補を開くと、用意されているFAQの回答を読めます。

まずはデモで使い方を試せます。質問例を選んで「FAQを探す」を押し、候補のFAQを開いてみてください。「検索方法を比べる」では、検索だけの場合と、候補をAIで確認する場合を切り替えられます。

デモは架空の社内FAQ18件と質問例6件を使い、実際に収録したAPIの結果と各処理の待ち時間を再生します。自由入力やライブAPIへの接続は行いません。この記事の精度・速度の評価に使った1,786件・587問とは別のデータです。

ここから先は、この画面の裏側で、FAQ全件をLLMに渡すか、候補を絞って並べ直すかを比較します。全件読み自体はこのデモでは再生していません。

## 今回の記事に加える文

自然な言葉で質問し、候補のFAQを開いて既存の回答を読む。今回も、こうした検索アプリを想定しています。

同じデモの「検索方法を比べる」で、検索のみ・Flashによる確認・Decisionによる確認を切り替えられます。「質問を変換→FAQを探す→AIで確認」のどこで待ち時間が発生するかも見られます。

デモは独自の架空FAQと質問例に対する、記録済みAPI結果の再生です。記事のベンチマークとは別データであり、この小さなデモの順位や待ち時間から性能の優劣を判断するものではありません。候補数もデモでは10件に固定しています。

以下では、この検索アプリの候補の並べ直しをDecision APIに置き換えると、精度・待ち時間・費用がどう変わるかを、同じ1,786件・587問で確かめます。
